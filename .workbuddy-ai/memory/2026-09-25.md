# 2026-09-25

## 定位并修复「蓝牙连上了但 Codex 显示功能受限、要等十多分钟」

### 根因（实测确认，不是推断）

BLE 绑定的两半不一致：板子这半被历史的「绑定代次迁移」（`kBondRevision` 2→5）
清空，Windows 那半还留着旧 LTK。链路永远不加密 → HID 报告特征（要求加密）的写入
被本地拒掉（`hid_write ... 0x57`）→ 桌面端显示「已连接，功能受限」。

- 09-23（绑定完好）：应用启动后 **175 ms** 握手成功。
- 09-25（绑定已坏）：**9 分 40 秒**才成功。同一固件、同一机器。

「重启后又失效」= 每次重新烧录都触发一次迁移，又把板子那半清一次。

### 关键否证：不要加 `esp_ble_set_encryption()`

在 `ESP_GATTS_CONNECT_EVT` 里请求安全，实测把链路打成 16 ms 一轮的断连循环：

```
I (5011) ble: connected peer e0:0a:f6:80:71:d2
I (5011) ble: security requested id=0
I (5011) ble: host connected id=0 bonds=0
W (5026) BT_APPL: bta_dm_ble_smp_cback remove bond,rsn 102, BDA:0xE00AF68071D2
W (5027) BT_HCI: hcif disc complete: hdl 0x1, rsn 0x13
I (5028) ble: host disconnected id=0 reason=0x13
W (5029) ble: pairing failed reason=0x66
```

主机根本不回答 Security Request，直接拆链。实现上也绕不过：peripheral 恒为 slave，
`btm_ble_set_encryption()` 只有 master 分支直接启动链路层加密，其余一律 fall through
到 `SMP_Pair()`，所以 `ESP_BLE_SEC_ENCRYPT` 与 `..._NO_MITM` 发出的是同一个包。

### 主机侧唯一有效的清理手段

`windows_companion.py --repair-pairing` 的 `UnpairAsync` 会连 LTK 一起删掉
（返回 `Unpaired`；随后的 `pair=Failed` 是预期行为，控制台进程弹不出 ConfirmOnly
确认框）。清完之后 `BluetoothLEDevice.FromBluetoothAddressAsync()` 反而返回 null
——这正是「记录干净」的表现。清理后必须在 Windows 设置里手动配对一次。

### 本次改动（`main/codex_ble.cpp`）

- `CODEX_BLE_BOND_REVISION` 默认 `0` = **不清绑定**（原来是启动时自动清）。
- `CODEX_BLE_SECURITY_ON_CONNECT` 默认 `0` = 不在连接事件里请求安全。
- 连接日志加 `bonds=N`；`bonds=0` 就是绑定不一致的判据。
- `kBondGeneration` 保持 `0x5D`（广播 `28:84:85:B2:1C:73`），未换地址。

固件已编译烧录（1 890 048 B）。README 新增 6.17 节，7.1 节改写「不要做的事」。

## 追加（12:20）：`28:84:85:B2:1C:73` 这条地址彻底废了，已换地址

清掉主机记录后出现更隐蔽的坏状态：板子每 22 秒一轮「连上 → `pairing complete` →
只读电池(63/64/65)和配额(68) → 空闲被拆(reason 0x8)」，**从来不碰 HID 服务（55–62）**。
配套现象：`hid_caps.py` 报 no HID interface、`ble_host_diag.py` 里连
`BTHLE\DEV_…1C73` 节点都不存在，而 WinRT 却说 `conn=Connected, paired=false,
canPair=false`。同时**被连接期间板子停止广播**，所以「添加设备」也扫不到它
——这就是用户报的「电脑蓝牙搜索不到 Codex Micro」。

结论：这条地址的记录修不回来，按 README 6.16 的既定逃生路径换地址。

- `kBondGeneration` `0x5D` → `0x5F`（广播 `28:84:85:B2:1C:75`，Windows 从未见过）。
- `CODEX_BLE_BOND_REVISION` `0` → `6`（把板子侧旧的对端绑定也清一次）。
- 新增启动日志：`ble: bond migration: stored=%u requested=%u read=%s bonds=%d`，
  实测 `stored=6 requested=6 read=ESP_OK bonds=0` —— 两侧都干净。
- 已烧录，板子持续广播、`conns=0`，等用户在设置里配对。

### 额度同步（用户问「官方有没有更好的办法」）

官方通道是 Codex 桌面端自带的 `CodexMicroService`（HID RPC），推的是会话状态、
灯光、`device.status`，**不含额度**。官方没有 Windows 端伴生程序；上游
`huaxx-lab/codex-micro-stopwatch` 的 Bridge 只有 macOS 且同样不推额度。
额度环是本移植版自加功能，只能由本机程序读额度再写私有特征。
建议是把 `windows_companion.py --watch` 注册成登录自启，而不是换数据源。
